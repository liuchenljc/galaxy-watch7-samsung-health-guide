## 二、快速排查流程（问题再现时的处理顺序）

```
┌─ 先分类：症状属于哪一类？
│
├─【手表/手机互相推、功能不生效】 ────────────── 走「链路三查」
│   1. 手机是否 root 可用？            adb shell "su -c id"        → 见 A/B
│   2. 模块是否在跑？                  ls /data/adb/modules/       → 见 B1
│   3. MIUI 三层是否放行？             → 见 C1/C2（最常见！）
│      ① powerkeeper 省电库 ② 后台弹出界面 ③ 触控
│
├─【三星应用本身打不开 / 页面异常】
│   1. 是卡登录页 → D1
│   2. 是闪退     → D2（厂商白名单）
│   3. 是"服务不可用" → D4（地区门）
│   4. 是"去手机上/去手表上"循环 → D3（★setup_init 总开关）
│
├─【手表连不上 / 配对问题】
│   1. 弹"需要重置手表"？ → F1（先别重置！）
│   2. 提示"无法打开三星健康"？ → F3（Wear 数据层）
│   3. 完全搜不到手表？ → E1（无线调试两个端口）/ F1
│
└─【改完没效果】
    1. 确认改动真的生效了吗 → G1（logcat 自我匹配陷阱）
    2. 确认属性/值被应用真的读到了 → B4（Build 冻结）
    3. 确认判据写对了 → G2
```

### 判断分支速查（三句话）

1. **"手机毫无反应"** → 99% 是 MIUI 拦截（C2 后台弹出界面 / C1 省电库）
2. **"功能入口灰掉/显示不可用"** → 99% 是地区门（D4）
3. **"流程走一半互相推"** → 99% 是 SHM 初始化开关没写（D3）

## 四、严重程度定义

| 级别 | 含义 |
|---|---|
| **P0** | 直接导致核心功能不可用；不知道就会绕远路（本包最重要的部分） |
| P1 | 影响体验或增加大量排查时间，但可绕过 |
| P2 | 一次性配置问题，配好就不再出现 |

## 五、使用约定

- 命令中的 `$A` / `$ADB` 均为 adb 调用前缀，各文档开头有本机定义
- 形如 `<手机序列号>` / `<手表IP:端口>` 的尖括号内容是**需按本机环境替换的占位**
- 所有"根因"均来自本会话实测证据（logcat / 文件内容 / 行为观测），未经验证的推测已标注 ⚠️
