# 05 · 手表侧（Wear OS 调试与侧载）

> **环境事实（本机，2026-10-03）**
> - adb：`%USERPROFILE%\Desktop\platform-tools\adb.exe`（下文以 `$ADB` 代指，脚本开头 `ADB="%USERPROFILE%/Desktop/platform-tools/adb.exe"`）；手机：小米14（houji，HyperOS 3.0.306 / Android 16，已 root：SukiSU Ultra，su 可用），adb 序列号 `<SERIAL>`
> - 手表：Galaxy Watch7 SM-L310（One UI 8 Watch / Wear OS 16，蓝牙 MAC `<WATCH_MAC>`，Wear 节点 `<DEVICE_ID>`，**无 root**）；无线 adb 地址与端口**每次都会变**，用 `adb mdns services` 重新发现
> - 应用版本：三星健康 7.00.6.011 / 健康监测器(SHM) 1.5.2.002 / Galaxy Wearable 2.2.70 / Watch7插件 2.2.15 / 手表端 SHM 1.2.7.003（官方）
> - 已装框架：Zygisk-Next(zygisk_rezygisk) + Vector v2.2(LSPosed 现名, zygisk_vector) + 模块 shm_watch7_fix(v5 自愈) + 伪装模块 com.arnold.spoofsamsung.Hook(v7/v8)
> - Git Bash 约定：所有 adb 批处理脚本开头必须 `export MSYS_NO_PATHCONV=1`；给 adb 的本地文件路径用 `C:/` 风格
> - 占位符约定：`<watch>` = 手表当前无线 adb 目标（`<IP:端口>`，无线调试主页面显示的地址）；`<apk>` = 本地安装包路径（C:/ 风格）
> - 严重程度分级：P0=核心功能不可用；P1=绕过成本高；P2=一次性配置

## E1 · 手表无线调试：配对码连不上（两个端口搞混）

**影响范围**：所有手表侧 adb 操作 ｜ **严重程度**：P1

### ① 问题现象

- `adb pair <IP:端口> <配对码>` 超时或 offline；或 pair 成功了 connect 却失败。
- 用户经常发错页面：Wear OS 无线调试有**两个页面、两个端口**。

### ② 报错关键信息（原文代码块）

```
adb pair <IP:端口> <码>    → 超时 / offline
或：pair 成功了，connect 却失败
```

本会话成功实例（IP/端口每次都变，仅对照结构）：

```
pair    <LAN_IP>:34047    → 成功
connect <LAN_IP>:35167    → 成功
```

### ③ 根因分析

Wear OS 无线调试有**两个页面、两个端口**：

1. 「无线调试」**主页面**显示的『IP 地址和端口』→ **adb connect** 用；
2. 『使用配对码配对设备』**子页面**显示的 6 位码 + 端口 → **adb pair** 用。

拿错页面的端口，就会出现 pair 超时/offline，或 pair 成功但 connect 失败。

### ④ 快速定位要点

- 先分清手里两个端口各来自哪个页面：**pair 只用配对子页面的端口 + 6 位码；connect 只用主页面的端口**。
- 用户发来两个端口就逐个试：先按上面的对应关系配，不通再交换。
- 手表重开无线调试后端口会变，先 `adb mdns services` 看当前可发现的实例。

### ⑤ 解决方案与操作步骤

```bash
export MSYS_NO_PATHCONV=1
ADB="%USERPROFILE%/Desktop/platform-tools/adb.exe"

# ① pair：用『使用配对码配对设备』子页面的端口 + 6 位配对码
"$ADB" pair <配对页IP:端口> <6位配对码>

# ② connect：用『无线调试』主页面的『IP 地址和端口』
"$ADB" connect <主页IP:端口>

# ③ 确认
"$ADB" devices
```

本会话实例：pair `<LAN_IP>:34047` 成功 → connect `<LAN_IP>:35167` 成功。

### ⑥ 验证方式

- pair 输出 `Successfully paired to ...`；
- connect 后 `adb devices` 中手表条目为 `device`。

### ⑦ 预防措施

- ⚠️ 手表**重新配对后 mDNS 标识会变**（`adb-RFAX821PGLX-6MxFhT` → `adb-RFAX821PGLX-PDtReO`），**必须重新 adb pair**；IP 也会变（<LAN_IP>→209→214）。
- 每次开始手表侧操作先用 `adb mdns services` 重新发现，不复用旧地址/旧端口。

<a id="E2"></a>
## E2 · 手表 adb 一会儿就断（device offline / not found）

**影响范围**：手表侧诊断效率 ｜ **严重程度**：P1

### ① 问题现象

之前连得好好的，突然 offline / not found。

### ② 报错关键信息（原文代码块）

```
$ adb devices
<IP:端口>    offline        # 或条目直接消失（not found）
```

### ③ 根因分析

1. Wear OS **熄屏即断**：屏幕一灭，adbd 就停；
2. adb server 重启会丢掉所有无线连接；
3. IP/端口轮换：DHCP 换 IP + 每次开无线调试端口都变。

### ④ 快速定位要点

- `adb devices` 看状态：`offline` = 连接还在但手表侧 adbd 已停；条目消失 = 地址/端口已轮换。
- 先点亮手表屏幕（抬腕/按表冠），再 `adb mdns services` 拿最新地址。

### ⑤ 解决方案与操作步骤

点亮手表屏幕（抬腕/按表冠）→ `adb mdns services` 拿最新地址 → connect → 立刻操作。
把『起 daemon → connect → 取数』压进**同一条短命令**，拆开跑必掉线：

```bash
export MSYS_NO_PATHCONV=1
ADB="%USERPROFILE%/Desktop/platform-tools/adb.exe"

"$ADB" mdns services && "$ADB" connect <IP:端口> && "$ADB" -s <IP:端口> shell '<取数命令>'
```

### ⑥ 验证方式

`adb devices` 里手表为 `device`。

### ⑦ 预防措施

- 手表侧操作尽量集中在一个时间窗内完成。
- 重要数据先拉到电脑。
- 任何导致 adb server 重启的操作（如 `adb kill-server`）都会丢掉所有无线连接，手表侧操作进行中不要做。

## E3 · 手表无 root（su: inaccessible or not found）

**影响范围**：手表侧诊断深度 ｜ **严重程度**：P2

### ① 问题现象

- 手表上 `su -c id` 报 `su: inaccessible or not found`；
- 读 `/data/misc/bluedroid/bt_config.conf` 报 Permission denied。

### ② 报错关键信息（原文代码块）

```
$ su -c id
su: inaccessible or not found

# 读 /data/misc/bluedroid/bt_config.conf：
Permission denied
```

### ③ 根因分析

Watch7 是 user build，**无法 root**（也没有可靠的 .watch root 方案）。

### ④ 快速定位要点

不要浪费时间试 su——直接改用 adb 可用的手段（手表上均可执行）：

- `pm list packages` / `dumpsys package`
- `dumpsys bluetooth_manager`
- `logcat`
- `cmd package resolve-activity`
- `screencap`
- `uiautomator dump`
- `am start`（exported 的）

### ⑤ 解决方案与操作步骤

- 读不了的东西（/data 下的私有文件、蓝牙密钥）→ **放弃或换行为观测**（logcat / dumpsys / 界面表现）。
- 需要手表 root 才能做的事（改 CSC、装 Xposed）→ 判定为**『手表侧无法突破』**，方案里换路径。

### ⑥ 验证方式

无专项验证（源记录标注为「—」）；前提可随时用 `su -c id` 复确认——仍报 `su: inaccessible or not found` 即维持该前提。

### ⑦ 预防措施

把『手表无 root』写进方案前提，避免设计依赖手表 root 的修复。

<a id="E4"></a>
## E4 · 重新配对后手表上的侧载应用消失

**影响范围**：手表侧载功能（备用 ECG、抗氧化入口） ｜ **严重程度**：P1

### ① 问题现象

手表走『连接到新手机』重配后，侧载的 app（GeminiMan、抗氧化指数启动器）消失；官方应用（SHM 1.2.7.003）自动回来（lastUpdateTime 变为新配对时间）。

### ② 报错关键信息（原文代码块）

无报错，表现为包消失：

```
$ pm list packages | grep -iE 'geminiman|skya'
（无输出 —— 侧载包已被重配流程清掉）
```

### ③ 根因分析

重配流程只保留 Galaxy Store / 系统应用，sideload 的应用被清。

### ④ 快速定位要点

```bash
# 系统应用未动（本机 241 个）
"$ADB" -s <watch> shell pm list packages | wc -l

# 看侧载包还在不在
"$ADB" -s <watch> shell pm list packages | grep -iE 'geminiman|skya'
```

（脚本开头记得 `export MSYS_NO_PATHCONV=1`。）

### ⑤ 解决方案与操作步骤

重装即可（一分钟）。安装包备份在电脑 `可选应用/` 目录：

```bash
export MSYS_NO_PATHCONV=1
ADB="%USERPROFILE%/Desktop/platform-tools/adb.exe"
"$ADB" -s <watch> install -r <apk>
```

### ⑥ 验证方式

- `pm list packages | grep -iE 'geminiman|skya'` 有输出；
- 启动测试通过。

### ⑦ 预防措施

- 保持侧载 APK 在电脑 `可选应用/` 目录的备份可用（本会话已有）。
- 每次重配后用 ④ 的 grep 检查一遍侧载包。

## E5 · 分不清手表上的 SHM 是官方版还是 mod 版

**影响范围**：版本管理 ｜ **严重程度**：P2

### ① 问题现象

不确定手表上的 SHM（com.samsung.android.shealthmonitor）该不该动、是什么版本。

### ② 报错关键信息（原文代码块）

无报错，关键区分在 versionName：

```
versionName=1.2.7.003.dante63    ← mod 版（dante63 mod，历史安装过）
versionName=1.2.7.003            ← 官方版（当前）
```

### ③ 根因分析

历史原因装过 dante63 mod（versionName 带 `.dante63` 后缀），后来换成了官方版。

### ④ 快速定位要点

```bash
"$ADB" -s <watch> shell dumpsys package com.samsung.android.shealthmonitor | grep versionName
# 带 .dante63 后缀 = mod；纯版本号（1.2.7.003）= 官方
# 另看 lastUpdateTime 与 firstInstallTime，判断是否被重装过
```

### ⑤ 解决方案与操作步骤

本项目最终用**官方 1.2.7.003**（targetSdk 36）。

教训：**手上的旧源码 ≠ 手机上运行的版本**——要改模块，先 baksmali『正在跑的那份』：

```bash
# ① 找到正在运行的 APK 路径
"$ADB" -s <watch> shell pm path com.samsung.android.shealthmonitor
# ② pull 回本地（C:/ 风格路径）
"$ADB" -s <watch> pull <上一步输出的apk路径> C:/<本地目录>/shealthmonitor.apk
# ③ 反编译这一份，而不是手上的旧源码
baksmali d C:/<本地目录>/shealthmonitor.apk
```

### ⑥ 验证方式

无专项验证（源记录标注为「—」）；可用 ④ 的 dumpsys 输出复核当前 versionName 为 `1.2.7.003`（官方）。

### ⑦ 预防措施

- 任何针对手表应用的修改前，先确认正在运行的版本（④）。
- 改动基于『正在跑的那份』的反编译产物，而不是手上的旧源码。

## E6 · 手表卡在横屏 / 自动旋转关不掉

**影响范围**：手表 UI 体验 ｜ **严重程度**：P2

### ① 问题现象

手表充电界面旋转后，UI 卡在横屏出不来。

### ② 报错关键信息（原文代码块）

无报错，关键 settings 值：

```
settings get system user_rotation          → 1    # 0=竖 1=横
settings get system accelerometer_rotation → 0    # 自动旋转已关闭
```

### ③ 根因分析

`user_rotation` 被记成 1（横屏）+ `accelerometer_rotation=0`（自动旋转关闭）→ 卡在横屏。

### ④ 快速定位要点

```bash
"$ADB" -s <watch> shell settings get system user_rotation            # 0=竖 1=横
"$ADB" -s <watch> shell settings get system accelerometer_rotation   # 0=关闭自动旋转
```

说明：手表**没有旋转 UI 开关**——设置→显示里只有亮度/息屏提醒/自动调节亮度；快速面板可注册磁贴里只有三星 NFC 一个。手机侧的旋转开关在控制中心磁贴。

### ⑤ 解决方案与操作步骤

```bash
"$ADB" -s <watch> shell settings put system user_rotation 0
"$ADB" -s <watch> shell settings put system accelerometer_rotation 0   # 锁定
```

### ⑥ 验证方式

screencap 确认竖屏：

```bash
"$ADB" -s <watch> exec-out screencap -p > C:/<本地目录>/watch_screen.png
```

### ⑦ 预防措施

- 手表端没有旋转 UI 开关，卡横屏直接用 ⑤ 的 adb 命令切回，不要在设置里找开关。
- 触发场景是充电界面旋转，充电时避免旋转操作。
