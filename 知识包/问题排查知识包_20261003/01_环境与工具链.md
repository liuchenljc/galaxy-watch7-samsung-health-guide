<a id="A1"></a>
## A1 电脑没有 adb / adb 版本不匹配

**影响范围**：所有 adb 调试的前提 ｜ **严重程度**：P1

**现象**
- `command -v adb` 为空
- 或 adb 命令报 `adb server version (39) doesn't match this client (41)`

**报错关键信息**
```
NO_ADB
adb server version (39) doesn't match this client (41); killing...
```

**根因**
- 本机没装 platform-tools
- 或系统里存在**另一个 adb 服务进程**（别的工具/模拟器带的），与当前客户端版本不同

**快速定位**
```bash
command -v adb || echo NO_ADB
ls /c/platform-tools/adb.exe /c/Users/<用户名>/AppData/Local/Android/Sdk/platform-tools/adb.exe 2>/dev/null
```

**解决方案**
```bash
# 下载官方 platform-tools（dl.google.com 本机可直连）
mkdir -p <工具目录> && curl -L --fail -o /tmp/pt.zip \
  https://dl.google.com/android/repository/platform-tools-latest-windows.zip
unzip -q -o /tmp/pt.zip -d <工具目录>/
<工具目录>/platform-tools/adb.exe version
```
版本不匹配时：**直接让 adb 自己重启服务**（它会 kill 掉旧 server）：
```bash
"$A" devices        # 报错后会自动 killing 并重启
```

**验证**
`adb version` 有输出，`adb devices` 能列出设备

**预防**
- 把 adb 路径写进脚本变量（见 [09_附录](09_附录_环境快照.md)），不要依赖 PATH
- 同时存在多个 adb 时，**只用其中一个**，避免 server 反复互杀

<a id="A2"></a>
## A2 ★ Git Bash 路径转换破坏 adb 参数（P0）

**影响范围**：所有含本地路径参数的 adb 命令（screencap / pull / push 等） ｜ **严重程度**：P0

**现象**
- 明明参数是对的，adb 却报 usage 或找不到文件
- `adb shell screencap -p /sdcard/x.png` → 打印 screencap 的 usage
- `adb pull /sdcard/x.png /c/Users/…/out.png` → `cannot create file/directory`

**报错关键信息**
```
usage: screencap [-ahp] [-d display-id] [FILENAME]
adb: error: cannot create file/directory '/c/Users/.../out.png': No such file or directory
```

**根因**
Git Bash（MSYS）会把长得像 Unix 路径的参数**自动转换成 Windows 路径**：
- `/sdcard/x.png` 被转成 `C:/Program Files/Git/sdcard/x.png` 传给 adb → 手机上不存在
- 反过来，本地目标路径 `/c/Users/...` 在禁用转换后又原样传给 `adb.exe`，Windows 不认

**快速定位**
看报错里路径是否被改写：原本 `/sdcard/...`，报错里出现 `C:/Program Files/Git/...` 或反斜杠

**解决方案**（两条铁律）

```bash
# ① 每个 adb 命令前都导出这个（写进脚本开头）
export MSYS_NO_PATHCONV=1

# ② 给 adb.exe 的「本地文件路径」一律用 Windows 风格：C:/Users/... （正斜杠可以）
A="/c/Users/<用户名>/Desktop/platform-tools/adb.exe"      # bash 里执行 adb 本身用 /c/ 形式
"$A" pull /sdcard/x.png "C:/Users/<用户名>/out.png"        # 给 adb 的本地路径用 C:/ 形式
```

**反例（会坏）**
```bash
export MSYS_NO_PATHCONV=1
"$A" pull /sdcard/x.png /c/Users/<用户名>/out.png     # ❌ adb 收到 /c/... 不认识
```

**验证**
`"$A" shell screencap -p /sdcard/t.png && "$A" pull -q /sdcard/t.png "C:/Users/…/t.png"` 能成功出图

**预防**
把 `export MSYS_NO_PATHCONV=1` 和 `$A` 定义写在**每个脚本文件的开头**；路径规则写进脚本注释。

<a id="A3"></a>
## A3 `more than one device/emulator`

**影响范围**：多设备环境下的所有 adb 命令 ｜ **严重程度**：P1

**现象**
原本能用的命令突然报设备不唯一

**报错关键信息**
```
adb.exe: more than one device/emulator
```

**根因**
同时存在多个连接（USB + 无线 adb + 手表 + 离线残留记录）

**快速定位**
```bash
"$A" devices -l        # 看有几个 device / offline
```

**解决方案**
```bash
"$A" -s <序列号> shell ...          # 所有命令都带 -s
# 或动态取第一个在线设备
T=$("$A" devices | grep -v offline | grep "device$" | head -1 | cut -f1)
"$A" -s "$T" shell ...
```

**验证**
`adb devices` 后所有后续命令都带 `-s`，不再报错

**预防**
脚本里**永远动态解析 serial**，不写死也不省略 `-s`。

<a id="A4"></a>
## A4 设备 offline / not found

**影响范围**：设备连接与后续所有 adb 取数命令 ｜ **严重程度**：P1

**现象**
- `adb devices` 里设备显示 `offline`
- 或之前能用的序列号突然 `device 'xxx' not found`

**报错关键信息**
```
$ adb devices -l
<序列号>                 offline       ← 状态不是 device
adb: device '<序列号>' not found
```
（`unauthorized` = 手机上"允许 USB 调试"授权弹窗未点，同样不可用）

**根因**（三种）
1. **USB 线松/掉线**（最常见）
2. **手机锁屏/授权弹窗未点**（"允许 USB 调试"）
3. **手表无线 adb 熄屏断开**（Wear OS 特性，见 [05_手表侧](05_手表侧.md#e2)）
4. adb server 重启导致无线连接全丢

**快速定位**
```bash
"$A" devices -l                    # 看状态
"$A" mdns services                 # 无线设备：拿最新 IP:端口（会变！）
```

**解决方案**
```bash
# USB：重新插线 + 手机上点"允许 USB 调试"
# 无线：用 mdns 拿到最新地址后重连
W=$("$A" mdns services 2>/dev/null | grep adb- | head -1 | awk '{print $3}')
"$A" connect "$W"
# 还是不行：重启 adb 服务
"$A" kill-server; sleep 3; "$A" start-server; sleep 3
```

**验证**
`adb devices` 里目标设备为 `device`（不是 offline/unauthorized）

**预防**
- 把「起 daemon → connect → 取数」压进**同一条短命令**，拆开容易掉线
- 无线调试的 IP/端口**每次都会变**，不要写死

## A5 缺少 java / smali / 签名工具

**影响范围**：模块重打包 / 重签名流水线（用法见 B2/B3） ｜ **严重程度**：P2

**现象**
想重打包模块时发现没有 java、没有 apktool/baksmali

**报错关键信息**
```
$ java -version
bash: java: command not found
$ ls <工具目录>/*.jar
ls: cannot access '<工具目录>/*.jar': No such file or directory
```

**根因**
本机用的是"JRE + 独立 jar 包"的便携方案（不需要完整 Android SDK）

**快速定位**
```bash
command -v java && java -version
ls <工具目录>/*.jar
```

**解决方案**
本机工具链位置见 [09_附录](09_附录_环境快照.md)。核心是：
- **JRE 17**（不是 JDK，JRE 足够跑 jar）
- **baksmali/smali 2.5.2 + 依赖 jar**（反编译/汇编 dex）
- **uber-apk-signer.jar**（重签名）

用法要点见 [02_root与模块](02_root与模块.md#b2)。

**验证**
`java -jar uber-apk-signer.jar --help` 有输出

**预防**
工具链**不要发布到 GitHub**（体积大），本地留一份 + 文档写明来源。

<a id="A6"></a>
## A6 中文路径 + Git Bash 组合坑

**影响范围**：中文路径下的脚本运行与命令拼接 ｜ **严重程度**：P1

**现象**
脚本在中文路径（如桌面 `一键复刻/`）下运行异常，或 `grep` 报 `invalid option -/Users/...`

**报错关键信息**
```
ugrep: invalid option -/Users/<用户名>/xxx.txt
```

**根因**
- 中文路径 + `MSYS_NO_PATHCONV` 组合时，部分工具对参数解析异常
- 更常见的是**命令拼接错误**：路径被当成选项

**快速定位**
把命令单独跑一遍，看是"路径错"还是"引用错"

**解决方案**
- 统一 `export MSYS_NO_PATHCONV=1`
- 路径**加引号**：`grep "pattern" "$FILE"`，且 `grep` 的选项写在路径前
- 复杂脚本用 **Python 驱动 adb**（`subprocess` 传数组参数，不经过 shell 拼接），可彻底避开这类坑

**验证**
脚本重复运行结果一致

**预防**
能用 Python 就不要用 shell 拼字符串。
